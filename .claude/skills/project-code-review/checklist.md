# 리뷰 체크리스트

이 프로젝트에서 실제로 깨지기 쉬운 지점을 영역별로 모았다. 변경과 관련 있는 항목부터 본다.

## 버그·로직
- **회전각과 당첨 판정**: `spin()`은 칸 i의 중심이 12시 포인터에 오도록 `rotation ≡ -(i + 0.5) × 칸각도 (mod 360)`을 맞춘다. 칸 순서(12시에서 시계 방향), 지터 범위(칸 안쪽), 누적 `rotation` 계산을 바꿨다면 테스트 "회전각 공식"이 여전히 이를 덮는지 확인한다.
- **상태 전이**: `spinning`, `wheelStale`. 도는 중에 필터나 메뉴를 바꿀 때, 버튼을 연타할 때, `transitionend`가 오지 않아 폴백 타이머로 끝날 때 결과가 한 번만 기록되는지 본다.
- **경계값**: 후보 0개, 1개, 정확히 12개, 13개 이상. 오늘 나온 메뉴가 후보 전부일 때 다시 포함하는 처리.
- **날짜**: `dayKey()`는 로컬 날짜 기준이고 기록은 ISO(UTC) 문자열로 저장된다. 자정 전후, 다른 시간대에서 "오늘" 판정이 맞는지 본다.
- **저장값**: localStorage 읽기 실패, 깨진 JSON, 예전 스키마, 저장 실패(용량 초과, 프라이빗 모드). 메뉴는 `isValidMenu()`로 거르지만 기록 항목은 배열인지만 확인한다는 점을 염두에 둔다.
- **이벤트 위임**: `closest()`로 대상을 못 찾을 때, innerHTML로 다시 그린 뒤에도 핸들러가 동작하는지.
- **메뉴 추가 검증**: 앞뒤 공백, 중복 판정(이름+카테고리), id 충돌 가능성.

## 보안
- `innerHTML`에 들어가는 **모든** 사용자 값이 `esc()`를 거치는지. 메뉴 이름, 카테고리, id, `aria-label` 같은 속성 값까지 포함한다. 속성 안에서는 따옴표 이스케이프가 꼭 필요하다(`esc()`가 처리한다).
- localStorage 값은 신뢰할 수 없다. 다른 탭, 확장 프로그램, 사용자가 직접 바꿀 수 있으니 렌더링 전에 형태를 검증하는지 본다.
- 페이지 코드에 `eval`, `new Function`, 문자열을 넘기는 `setTimeout`이 없는지. 테스트 코드의 `new Function`은 하네스라 예외다.
- 외부 스크립트나 CDN을 새로 추가했다면 버전을 고정했는지, 정말 필요한지.
- 훅 스크립트(`.claude/hooks/`)가 커밋 명령 문자열을 셸 명령에 이어 붙이지 않는지(명령 주입).

## 접근성·모바일 UI
- 모든 조작이 키보드로 되는지. 클릭 가능한 것은 `<button>`이고, `:focus-visible` 스타일이 보이고, 토글 버튼에는 `aria-pressed`가 있는지.
- 결과가 스크린 리더에 전달되는지(`aria-live`). canvas는 `role="img"`와 라벨을 갖고, 원판 내용은 시각 정보뿐이라 결과 카드가 텍스트 대안 역할을 한다.
- 파스텔 배경 위 글자 대비가 4.5:1 이상인지(특히 `--muted` 회색 글자). 색만으로 상태를 구분하지 않는지.
- `prefers-reduced-motion`을 지키는지.
- 375px 폭에서 가로 스크롤이 없는지, 좌우 16px 여백이 있는지, 터치 대상이 충분히 큰지(약 44px 권장, 28px짜리 삭제 버튼 같은 것 주의).
- 입력 필드에 라벨이나 `aria-label`이 있고, 오류 메시지가 화면에 보이고 읽히는지.

## 가독성·성능
- 기존 관례를 따르는지: 한국어 UI 문구, 짧은 함수, "왜"를 설명하는 주석만. 이름이 역할을 드러내고 브라우저 전역을 가리지 않는지(예: 전역 `history`는 `window.history`를 가려서 `historyItems`로 바꿨다).
- `CATEGORIES`, `MEALS`, `MAX_SLICES` 같은 상수를 두고 값을 다시 하드코딩하지 않았는지.
- 다시 그리는 범위: 메뉴가 수십 개라 필터를 바꿀 때마다 전부 다시 그려도 괜찮다. 수백 개 이상을 가정한 변경이면 지적한다.
- canvas는 `devicePixelRatio`를 반영하고, resize는 디바운스하고, 불필요하게 매 프레임 그리지 않는지.
- 새 동작에 테스트가 있는지, 테스트가 내부 구현에 지나치게 묶여 있지 않은지.
