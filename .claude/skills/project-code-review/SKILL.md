# 프로젝트 코드 리뷰

## 이 프로젝트에 대해 알아둘 것
- `index.html` 하나에 CSS와 JS가 인라인으로 들어 있고 외부 라이브러리가 없다. 상태는 localStorage 키 두 개(`mealRoulette.menus`, `mealRoulette.history`)에 저장한다.
- `tests/roulette.test.js`가 가짜 DOM 위에서 인라인 스크립트를 그대로 실행해 동작을 검사한다.
- 커밋 전 훅(`.claude/hooks/pre-commit-check.js`)이 `npm run lint`(ESLint), `npm run build`(html-validate + dist 복사), `npm test`를 돌린다. 그래서 리뷰는 **도구가 잡지 못하는 것**, 즉 판단이 필요한 로직·보안·사용성 문제에 시간을 쓴다.

## 1. 범위 정하기
- 요청에 파일이나 범위가 있으면 그것만 본다.
- 없으면 `git status`, `git diff`, `git diff --staged`로 변경분을 찾는다. 변경이 없거나 아직 커밋이 하나도 없으면 `index.html` 전체를 대상으로 한다.
- 변경분만 리뷰하더라도 그 코드가 호출하거나 공유하는 함수와 상태 변수는 읽는다. 버그는 바뀐 줄 자체보다 기존 코드와 맞물리는 지점에서 더 자주 생기기 때문이다.

## 2. 기계 검사 먼저
`npm run lint`, `npm run build`, `npm test`를 실행해 결과를 적어 둔다. 실패한 검사는 그 자체로 **높음** 항목이다. 도구가 이미 잡는 문제를 손으로 다시 찾을 필요는 없으니, 결과만 옮기고 원인을 짚는다.

## 3. 체크리스트로 점검
[checklist.md](checklist.md)를 읽고 네 영역(버그·로직, 보안, 접근성·모바일 UI, 가독성·성능)을 차례로 본다. 체크리스트는 이 프로젝트에서 실제로 문제가 되기 쉬운 지점을 모은 것이다. 해당 사항이 없는 항목은 넘어간다.

## 4. 보고하기 전에 각 항목을 검증
- 항목마다 **구체적인 입력이나 상태 → 잘못된 결과**를 한 줄로 쓸 수 있어야 한다. 코드 흐름을 끝까지 따라가 보고, 필요하면 `node -e`로 짧게 재현한다.
- 시나리오를 쓸 수 없으면 심각도를 낮추고 "확인 필요"라고 표시하거나 뺀다. 추측성 지적이 섞이면 진짜 문제까지 신뢰를 잃는다.
- 줄 번호는 파일을 다시 읽어 확인한다. 틀린 위치를 주면 고치는 사람이 그만큼 헤맨다.
- 스타일 취향은 기존 코드의 관례와 어긋날 때만 지적한다.
- 리뷰만 하고 코드는 고치지 않는다. 무엇을 고칠지는 사용자가 정한다.

## 5. 보고 형식
아래 템플릿을 그대로 쓴다. 비어 있는 심각도 구간에는 "없음"이라고 쓴다.

```markdown
## 코드 리뷰 결과
**범위:** <파일 또는 diff 범위>
**기계 검사:** lint ✅/❌ · build ✅/❌ · test ✅/❌ (통과 수/전체)

### 🔴 높음 (n)
1. **<한 줄 요약>** — `index.html:123`
   - 영역: 버그·로직 | 보안 | 접근성·모바일 | 가독성·성능
   - 문제: <무엇이 왜 잘못됐는지>
   - 실패 시나리오: <입력/상태> → <잘못된 결과>
   - 제안: <고치는 방향, 필요하면 짧은 코드>

### 🟠 중간 (n)
### 🟢 낮음 (n)

### 잘된 점
- <있을 때만 1~3개>

### 총평
<한두 문장. 지금 상태로 커밋해도 되는지>
```

심각도 기준:
- **높음**: 사용자가 실제로 겪는 오동작, 데이터 손실, 보안 취약점, 기계 검사 실패
- **중간**: 특정 조건에서만 생기는 버그, 키보드·스크린 리더 사용자가 막히는 접근성 문제, 체감되는 성능 문제
- **낮음**: 가독성, 작은 개선, 방어 코드 보강

같은 심각도 안에서는 영향이 큰 순서로 적는다.

### 항목 예시
1. **메뉴 이름이 이스케이프되지 않은 채 innerHTML로 들어감** — `index.html:640`
   - 영역: 보안
   - 문제: `renderMenuList()`가 `m.name`을 `esc()` 없이 템플릿에 넣는다.
   - 실패 시나리오: 메뉴 이름에 `<img src=x onerror=alert(1)>` 입력 → 목록을 그릴 때 스크립트 실행
   - 제안: `${esc(m.name)}`로 감싼다. aria-label 같은 속성 값에도 똑같이 적용한다.
